# Mobile storefront menu

`/` presents the complete active menu in category order on a mobile-only storefront. The page renders semantic category sections and product rows on the server. The header and menu have separate Suspense boundaries so the page frame and useful loading state can stream while settings/session and catalog reads finish. The category tabs and each add-to-cart button are the only menu client islands; product data is not handed to a single list-wide Client Component.

The menu reads the existing public catalog application service once. That service batches category, product, addition, stock-orderability, and sold-count queries rather than querying per product. Its public projection excludes persistence documents, stock quantities, costs, and admin fields. The view narrows the projection further to the card fields; addition details are reserved for the forthcoming product-options flow. Current menu caps are 500 categories, 500 products, and 5,000 available additions. Exceeding a cap fails the menu read instead of silently hiding the remaining items. Revisit these limits and HTML size before growing beyond a small café catalog.

The public projection is cached under `storefront-menu-v1` for up to 30 seconds. Successful category and product mutation routes, plus media replacement, invalidate that tag after their service response, so failed writes leave the cache intact. The time limit is a safety net for changes made outside those HTTP routes; a multi-instance deployment needs a shared Next cache/invalidation strategy. Cart mutations and checkout never trust cached menu prices: the cart service reprices against current products.

The tab links are real `#category-*` anchors and work without JavaScript. JavaScript adds smooth scroll and active-section tracking. An initial page load without JavaScript cannot swap a streamed React Suspense fallback for fetched content, so the fallback links to `/menu/basic`, which renders the same cached menu in one server response without a Suspense boundary. Cart controls require JavaScript and customer authentication; the basic version remains readable without either. A failed catalog read shows a Persian retry state, and an empty catalog shows an explicit empty state.

Product media uses a fixed 88×88 slot and the existing small optimized media variant. Missing media IDs show the café icon. Product descriptions are line-clamped, and controls retain 44px touch height. The internal sample at `/internal/menu-preview` is clearly labelled, not indexed, and does not depend on local infrastructure; it supports visual and headless browser checks.

Run `npx playwright test tests/e2e/menu-page.spec.ts` for RTL category synchronization, no-JavaScript content, accessibility, and payload checks. The representative 18-product preview must stay below 350 KB of document transfer and 700 KB of script transfer. These are regression ceilings, not production performance targets; the production catalog should be monitored separately as content grows. Unit tests cover the lean card projection and a 500-product serialization bound.
