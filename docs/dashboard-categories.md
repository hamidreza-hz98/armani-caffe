# Dashboard category management

`/dashboard/categories` reads the category service directly during server rendering. It shows all non-deleted categories (up to the backend limit of 500), product counts from the product module's bounded projection, URL-driven name/status filters, a desktop card grid, and a compact mobile list. Owners can create, edit, reorder, disable, and delete; cashiers only read. The slug is generated by the backend and shown read-only.

Owners may drag a category by its handle with a mouse or touch, or use the adjacent up/down buttons with keyboard or touch. Reordering is enabled only when all categories are visible. The UI retains the last confirmed order while saving; the server's `orderRevision` guard rejects concurrent changes. On a conflict, the UI reloads the authoritative order and reports the conflict instead of showing an uncommitted arrangement.

The editor uses the shared ready/public media picker and confirms before discarding unsaved changes. Disabling a published category warns that dependent products will disappear from the public menu. The delete dialog displays the active product count and disallows deletion when products depend on the category; the server independently enforces the same rule. Successful category mutations invalidate the cached storefront menu through the existing route handler.

Run `npm run test:e2e:categories` for isolated browser coverage of create/edit, media selection, status, mouse/touch/keyboard reorder, conflict recovery, deletion impact, stale edits, mobile accessibility, and public menu invalidation. The existing `categories.test.ts` integration suite covers transactional behavior and permissions.
