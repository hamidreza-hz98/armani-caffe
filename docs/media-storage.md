# Private media infrastructure

Use `createMediaStorage()` from the media server boundary. The `MediaStorage` application port hides S3/MinIO details. Storage does not create MongoDB MediaAsset records: future media application services must save returned object descriptors and enforce entity-level permissions. Derive the owner ID from authenticated server context, never from an untrusted request. Owner scoping here is an additional guard, not a replacement for authorization. There is no public upload/list route or bucket enumeration method.

## Limits and lifecycle

- Accept static JPEG, PNG, or WebP only, 1 byte–10 MiB, at most 16 million decoded pixels. Decode and re-encode before persistence; neither filename nor declared MIME is authoritative. A declared/detected mismatch is rejected. No executable SVG or arbitrary documents are accepted.
- `upload` produces a normalized WebP original (fits within 4096×4096), 320px and 1280px variants, without EXIF/IPTC/XMP metadata. EXIF orientation is applied before metadata is removed. Decoder work has a ten-second processing limit per output. Bulk uploads accept 1–5 images, run sequentially to bound memory, and return separate safe success/failure results.
- Keys are generated by the server as `media/v1/<owner-id>/<random-uuid>/<sha256>-<variant>.webp`. Replacement uploads always get a fresh UUID and hash. Never overwrite approved keys. Do not accept user-supplied paths, bucket names, or prefixes.
- AWS managed uploads use 5 MiB parts, two parallel parts, a 30-second deadline, and `leavePartsOnError=false`. Failed variants cause sibling-object cleanup. A killed process or unavailable storage can still leave an orphan; the lifecycle aborts incomplete multipart transfers after one day. `media.cleanup_required` logs include the opaque upload ID/key for operator recovery. Reconcile these keys against MediaAsset references before deleting them; finalized media has no automatic TTL.
- `prepareUpload` returns a 120-second signed **POST** policy with an exact server-generated staging key, exact byte-size range, declared content type, and `no-store`. Browser multipart/form-data fields must be copied exactly; append the file last. This is a multipart form upload, distinct from S3 multipart parts used for large server transfers. There are no browser-managed S3 multipart sessions in this task.
- Upload tickets are HMAC-signed, owner-bound, and valid for 15 minutes for finalization/cancellation. Finalization reads a bounded private staging object, checks size and detected type, creates normalized approved objects, and deletes staging. Concurrent/repeated finalization can produce separate immutable objects; it is not a business-level idempotent MediaAsset creation operation. Future services must deduplicate requests and reconcile unreferenced outputs.
- `cancelUpload` deletes staging. The bucket lifecycle deletes abandoned staging after one day (asynchronously, not exactly at 24 hours). Re-run `npm run infra:init:minio` to install `infra/minio/lifecycle.json` on an existing local bucket. Lifecycle installation is an explicit infrastructure operation, never performed by normal requests.
- `delete` is idempotent and owner-scoped; retry all the same keys on a partial deletion failure. Metadata lookup and signed reads only accept approved key shapes, never staging keys. Health checks are authenticated and verify configured bucket access.

## Privacy and caching

The bucket has no anonymous read/list policy; application credentials must be limited in production to this bucket/prefix. Signed URLs and tickets are bearer capabilities: do not log them, persist them in analytics, or put them in public caches. Upload signing credentials and the HMAC key never enter client modules. Rotation of `ENCRYPTION_KEY` invalidates outstanding upload tickets; their lifetime is short.

Stored approved objects carry `private, max-age=31536000, immutable` for trusted authenticated reads. Browser presigned downloads last 120 seconds and override caching to `private, no-store`, so revocation does not leave a long-lived browser cache. A later authorized proxy may adopt a private-cache policy deliberately. No shared/public CDN caching is enabled. Delete revokes future object reads but cannot recall bytes already downloaded.

## Real-MinIO tests

`npm run test:integration` includes `minio-media.test.ts` and requires real MinIO. Start local MinIO first (see local infrastructure guide), or set `MINIO_TEST_ENDPOINT`, `MINIO_TEST_ACCESS_KEY`, and `MINIO_TEST_SECRET_KEY` for a dedicated test server. Defaults match explicitly unsafe local Compose credentials. Tests create a random `armani-test-*` private bucket, install lifecycle rules, and delete only that bucket afterward. They never read `.env.local` or use the development bucket. CI needs a supported/available MinIO binary or container and permission to create/delete test buckets.

The tests cover upload/read/variant/delete, anonymous read/list denial, presigned upload/download, spoofed type/size, wrong-owner rejection, cancellation, bulk partial failure, sibling cleanup, actual S3 multipart transfer and injected multipart interruption. If MinIO is unavailable, the suite fails with setup guidance; it does not silently skip. Pure unit tests run without storage using `npm run test:unit`.

MinIO's community distribution is archived; deployment and new-machine provisioning require an explicit supported-storage decision. See [ADR 0003](adr/0003-private-media-storage.md).
