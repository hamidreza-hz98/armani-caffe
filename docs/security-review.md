# Security review (2026-10-04)

This is a code-and-test review, not a penetration test or production deployment approval. The trust boundaries are browser → route/action → application service → database, provider → callback → authoritative verification, and local bridge → realtime server → durable print job. The database, Redis, object store, payment provider and printer remain separate trust domains.

| Threat                                          | Current control / evidence                                                                                                                                                                                                                                                                                                                               | Remaining risk or action                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admin/customer session theft or role escalation | Separate `HttpOnly`, `SameSite=Strict` cookie names and server-side session/capability checks. Session rotation and revocation are tested in auth integration tests.                                                                                                                                                                                     | Deploy only behind HTTPS, with production cookie mode enabled. Protect operator devices and rotate secrets after compromise.                                                                                                                                                                                                 |
| CSRF and cross-origin WebSocket use             | Mutating HTTP handlers require an exact configured `Origin`; browser WebSocket rooms require an allowlisted origin and an authenticated session. Realtime periodically rechecks admin sessions.                                                                                                                                                          | A reverse proxy must preserve `Origin` and must not expose an alternate unguarded route.                                                                                                                                                                                                                                     |
| XSS and malicious media                         | Settings reject markup and constrain social/map inputs; media accepts raster formats, detects/normalizes images to WebP, and serves `image/webp` with `nosniff` from a private bucket. CSP blocks objects, frames and foreign script origins.                                                                                                            | Production CSP still permits inline scripts/styles for Next.js/MUI compatibility. Move to per-request nonces and verify streaming/cache impact before removing `'unsafe-inline'`. Do not expose MinIO directly as a public website origin.                                                                                   |
| NoSQL injection, mass assignment, IDOR          | Contracts allowlist fields and validate IDs; service methods authorize principals and scope customer-owned resources. Lists are bounded.                                                                                                                                                                                                                 | Keep new mutations behind the same contracts and service checks; route guards alone are insufficient.                                                                                                                                                                                                                        |
| SSRF / path traversal                           | Map/social URLs are allowlisted; provider redirects require adapter allowlisted origins; media object keys are generated and pattern-checked.                                                                                                                                                                                                            | Review each new payment adapter's outbound URLs and callback fields against its official documentation.                                                                                                                                                                                                                      |
| Brute force / replay                            | Auth throttling, bounded bodies, provider-state check plus authoritative verification, transaction idempotency, print job delivery IDs and ACK attempts.                                                                                                                                                                                                 | Run ingress-level IP rate limiting and traffic monitoring as a second layer; application limits alone cannot absorb a volumetric attack.                                                                                                                                                                                     |
| Bridge impersonation / realtime ordering        | Bridge registration checks a secret; presence leases limit simultaneous bridge instances; ACKs must match printer, job, attempt and delivery ID. Frames are now processed serially per socket, preventing concurrent registration during asynchronous token validation. Canonical timestamps and consistent ACK results are validated at protocol entry. | Realtime listens on loopback. Terminate TLS/authenticate at the reverse proxy for remote bridges; never expose raw `ws://` or the bridge token to a browser. Rotate bridge token after device loss. Physical exactly-once printing cannot be guaranteed after a lost ACK—use the bridge journal and operator reconciliation. |
| Secret/log exposure                             | Server-only boundaries, encrypted settings secrets, redacted structured logs and no secret read-back.                                                                                                                                                                                                                                                    | Audit external log shipping and backup access controls in deployment.                                                                                                                                                                                                                                                        |
| Security headers                                | CSP, `nosniff`, frame denial, same-origin resource policy, no cross-domain policy, restrictive permissions and production HSTS for the served host.                                                                                                                                                                                                      | Add HSTS `includeSubDomains` only after confirming every subdomain supports HTTPS.                                                                                                                                                                                                                                           |

## Dependency audit

`npm audit --json` on 2026-10-04 found **0 critical, 5 high, 0 moderate, 0 low**. The five entries are one transitive chain: `eslint-config-next@16.3.6` → `@next/eslint-plugin-next` → `fast-glob@3.3.1` → `micromatch@4.0.8` → `braces@3.0.3`. The root advisory is [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), stack exhaustion on malicious deeply nested brace patterns. The advisory lists no patched `braces` version. This chain is in dev dependencies and processes repository-controlled lint patterns, not HTTP input. We accept this build-time risk temporarily; do not pass untrusted glob patterns to lint tooling, keep CI isolated, and recheck the advisory on dependency upgrades. `npm audit fix --force` proposes downgrading `eslint-config-next` to an incompatible major and was **not** run. `npm audit --omit=dev` reported **0 vulnerabilities** on the same date. Review deployment image contents before release to ensure development packages are actually excluded.

## Verification and release gates

- Regression tests: `tests/unit/realtime-security.test.ts`, `tests/unit/printing-protocol.test.ts`, `tests/unit/application-foundations.test.ts`.
- Run `npm run validate`, then real-service integration and E2E suites in an isolated environment. Exercise session revocation during active WebSockets, callback duplication, hostile upload, and printer restart against actual MongoDB/Redis/MinIO.
- Confirm TLS termination, proxy header forwarding, secret storage, backup permissions, ingress rate limits and CSP telemetry in staging. None is established by local unit tests.
