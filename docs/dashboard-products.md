# Product dashboard (Task 35)

`/dashboard/products` is a server-read, URL-filtered list. Search, status, category, orderability, sort and page can be shared as a link. Pagination is capped at 20 products per page and 25 pages, matching the catalog's 500-active-product limit. The read returns projected DTOs rather than Mongoose documents or stock rules. OWNER can select eligible rows and perform publish, unpublish or archive operations; each selected item is sent with its revision, processed independently, and a partial-result count is reported. Bulk operations are not presented as atomic. CASHIER can view the same list and details but receives no mutation controls or create route.

`/dashboard/products/new` creates a draft. The edit page sends the current revision with every save or transition; a conflict keeps local text visible and offers an explicit reload of the latest version. Publish checks required summary, positive price and public media locally for convenience; the product service remains authoritative about category, media, stock compatibility and lifecycle. A native modal media picker lazy-loads ready public assets. Addition and stock-rule sections are separate client modules, with keyboard-operable addition reorder buttons and fixed inventory-unit choices. The editor warns before refresh/closing and intercepts link navigation while changes are unsaved.

Run `npm run test:e2e:products` for isolated owner/cashier browser flows. Its temporary MongoDB fixture includes one public media record; browser image responses are simulated because local MinIO is not required for the form journey. `tests/integration/products.test.ts` tests the actual repository, pagination, role reads and lifecycle against a temporary replica set. Upload and media-storage behavior remains covered by the media module's separate tests.
