# Realtime printing operations

The local TypeScript client, simulator, Windows printer setup and operator recovery procedure are documented in [local print bridge](local-print-bridge.md).

Start MongoDB and Redis, then intentionally run `npm run db:migrate:up` and `npm run db:indexes:apply`. Configure printing settings with `enabled=true`, `automaticPrint=true`, a bridge ID, paper width and encrypted bridge token. Run `npm run realtime:work` as a **separate process** alongside Next.js. Expose its configured `WEBSOCKET_PATH` through a TLS reverse proxy for a remote bridge; the local process binds to `127.0.0.1:WEBSOCKET_PORT`. Never expose the raw local port or send bridge tokens in a URL. `GET /live` is process-only; `GET /ready` checks the Redis queue. Next.js readiness now reports `queue` and `realtime` separately from MongoDB, Redis and MinIO. Liveness is unchanged.

Protocol version 1 uses JSON. Connect to `/ws?role=bridge`, then immediately send `{"v":1,"type":"register","printerId":"...","token":"...","instanceId":"..."}`. Only one live connection per printer ID is admitted across processes. The server replies `registered` with heartbeat interval. Send `{"v":1,"type":"heartbeat","at":"2026-01-01T00:00:00.000Z"}` regularly, reply to WebSocket ping frames, and reconnect with backoff after close. The server's `print.job` contains job ID, invoice ID, printer ID, attempt, delivery ID, paper width and a self-contained Persian HTML receipt. Render it at 384/576 dots and use the ESC/POS raster adapter; **wait for the printer to report success** before ACKing. ACK schema: `{"v":1,"type":"ack","jobId":"24-hex","printerId":"...","attempt":1,"deliveryId":"uuid","result":"printed","at":"UTC ISO"}`; use `result:"error"` and an optional short `errorCode` for printer failure. An ACK must match the current leased attempt and arrive within five minutes of its timestamp. The server sends `ack.accepted` with current job status. Duplicate matching ACKs are idempotent.

Admin status is available at `GET /api/admin/orders/{orderId}/print` to authenticated owner/cashier, and at an admin-only WebSocket connection `/ws?role=admin` (same-origin cookie, fixed `tenant:default:print` room). Client-supplied room and tenant names are not accepted. The status API is authoritative after reconnect; socket updates are best-effort. Reprints begin with the audited invoice reprint endpoint described in [invoices](invoices.md), generating a new PrintJob against the original invoice.

The bridge must keep a **persistent local printed-job ledger**. If a print succeeded but its ACK was lost, the server retries; the bridge should ACK the redelivered job without printing it twice. MongoDB records queued/printing/printed/dead state and at most five attempts. Redis AOF retains the schedule; startup reconciliation repairs it from MongoDB if Redis was restarted or cleared. Inspect dead jobs via the status API and operator logs. Do not replay dead jobs without diagnosing printer failure and choosing an explicit recovery procedure.

Tests use a replica-set MongoDB plus a deterministic Redis schedule double to exercise claims, timeout, restart reconciliation, duplicate/error ACKs, two bridge instances and reconnect. The local infrastructure smoke command verifies real Redis AOF/restart persistence when Docker is available; it intentionally restarts Redis and should not run while serving real print jobs. See [ADR 0004](adr/0004-realtime-printing.md) for delivery guarantees and credential boundaries.
