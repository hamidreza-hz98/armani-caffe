# SEO, Persian RTL and accessibility audit — 2026-10-04

This audit covers the current local production build and representative automated browser states. It is not a substitute for Search Console inspection, assistive-technology testing, or approval of final café copy and photography.

| Favicon and sharing image                                                   | Owner-selected private-media-backed favicon when configured; otherwise `/armani-icon.svg`. Social cards use a same-origin 1200×630 PNG at `/social-preview`, avoiding an external or SVG-only crawler fallback. The social image is a generic brand graphic; it does not yet incorporate an owner-uploaded logo. |

Do not block private HTML in `robots.txt` merely to hide it: [Google documents](https://developers.google.com/search/docs/crawling-indexing/block-indexing) that a crawler must access a page to see its `noindex` directive. A sitemap should contain the preferred [canonical URLs](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), not every route. These controls are not authentication; private routes still require server-side access checks.

## Persian and accessibility evidence

- Root document uses `lang="fa"` and `dir="rtl"`; Vazirmatn is bundled locally. `formatToman` produces integer Persian-digit تومان amounts and `formatJalaliDate` uses the Persian calendar with Asia/Tehran presentation. Unit tests cover both helpers.
- Menu sections use a single H1, descending category/product headings, a main landmark, category navigation, accessible cart controls and explicit unavailable text. The no-JavaScript menu state links to the simpler server-rendered menu. The store shell has a skip link, Persian labels and reduced-motion-aware category scrolling. Mixed LTR order/reference/phone values are isolated with `bdi` or `dir="ltr"` in the inspected views.
- Existing storefront shell tests exercise 360, 390 and 430 px widths and axe scans; the new production-mode audit verifies metadata/crawl output, noindex pages, a 390 px menu without horizontal overflow, landmarks and no serious/critical axe findings. Existing shared-state and auth-flow tests cover selected focus/dialog behavior.
- Static source scan found no visible lorem ipsum or English form placeholder in the inspected storefront components. Fixed storefront brand wording was normalized to “آرمانی کافه.” This does not prove every dynamic error, payment provider message, or owner-authored content is linguistically reviewed.

## Remaining manual and deployment checks

1. On the production domain, verify `APP_URL` uses the intended HTTPS canonical host, test social previews in actual messaging/social debuggers, and inspect indexed URLs in Search Console after opting in. Owner-provided logos, favicon and final SEO copy need visual/crawl validation. With SEO disabled, an empty sitemap is intentional.
2. Review the real product catalog at 360/390/430 px and 200% zoom for clipped Persian text, image crops, tab overflow, table/card layouts, arrow direction and bidi values. Run keyboard-only and VoiceOver/TalkBack/NVDA checks for drawers, form errors, announcements and status transitions. Automated axe cannot certify those interactions or every touch target/contrast combination; use WCAG 2.2 as the [manual benchmark](https://www.w3.org/TR/wcag/).
3. The guest cart currently makes an unauthenticated cart request before showing the sign-in prompt, producing a browser 401 console entry. The noindex check was performed on server-rendered HTML to isolate indexing from that existing behavior. Remove that needless request in a cart-flow change, with corresponding fixture updates.
4. The menu H1 and some shell copy still use the fixed “آرمانی کافه” wording even if an owner changes the business title in settings. Confirm whether that title is meant to be customizable, then align visible copy and metadata together.
