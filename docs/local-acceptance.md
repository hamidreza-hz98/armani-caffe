# Local handoff and acceptance

This is a pre-deployment checklist, not a deployment procedure. Run commands from the repository's `armani-caffe` directory. Use Node 24.15.0 and npm 11.12.1. Never paste real credentials into a command, Git, test fixture, or issue. The local Compose credentials are deliberately unsafe for production.

## First run on a new development machine

1. Install Node/npm from `.nvmrc` and `package.json`, and Docker Engine/Desktop with Compose v2. Confirm `node --version`, `npm --version`, and `docker compose version`.
2. Run `npm ci`, `npx playwright install chromium`, and `npm run env:init`. Review `.env.local` against `.env.example` without printing its secrets. It is ignored by Git. On this Windows workstation the project-only `rsowner` MongoDB uses port 27018; port 27017 belongs to a different MongoDB instance. Use the exact replica-set URI documented in [local infrastructure](local-infrastructure.md) if using that fallback instead of Compose.
3. Run `npm run infra:up`, `npm run infra:init:mongo`, `npm run infra:init:minio`, and `npm run infra:status`. These use persistent local volumes. Confirm `npm run infra:smoke` **before** starting workers or accepting print jobs: it restarts Redis as a durability test. The MinIO initialization briefly restarts MinIO. If the pinned archived MinIO image is unavailable, stop and resolve the storage choice; do not silently substitute an unreviewed image.
4. Inspect `npm run db:migrate:status` and `npm run db:indexes:plan`; take a backup/change window before applying changes to an existing database. On a **new empty local project database**, run `npm run db:migrate:up -- --apply`, `npm run db:indexes:apply -- --apply`, `npm run db:seed -- --apply`, and `npm run db:smoke -- --apply`. Seed is idempotent and creates no administrator. Bootstrap an owner only through the explicit procedure in [admin auth](admin-auth.md), with a locally chosen secret supplied privately. Do not use the E2E owner fixture on a real database.
5. In separate supervised terminals run `npm run start:local` (or `npm run build`, then `npm run start`), `npm run realtime:work`, and `npm run bridge:run` on the café computer with a separately prepared `.env.bridge.local`. The standalone `npm run outbox:work` command currently has **no delivery handlers** and intentionally does not claim events; print outbox handling is registered in `realtime:work`. Do not count an idle standalone outbox process as operational delivery. See [realtime printing](printing-realtime.md) and [bridge setup](local-print-bridge.md).
6. Before enabling automatic printing, use the file simulator, verify one receipt and matching bridge/server ACK, then perform the [physical printer checklist](printing-resilience.md#manual-acceptance-checklist-for-the-actual-café-printer). A simulator proves protocol flow, not paper output.

Do not start a second Next.js process on port 3000 or run `npm ci` over an active Windows dev server: the native SWC module can be locked. Stop the server first, or verify a clean install in a disposable checkout. Stop services with `npm run infra:down` (keeps volumes). Volume deletion is a separate destructive opt-in command in [local infrastructure](local-infrastructure.md).

## Repeatable verification and manual pass

Run `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm run check:boundaries`, `npm run check:architecture`, `npm run test:unit`, `npm run test:integration`, `npm run test:e2e`, `npm run test:e2e:storefront`, `npm run test:e2e:dashboard`, `npm run test:performance`, and `npm run build`. `npm run validate` combines the baseline gates, but it does **not** include every browser journey, performance check, coverage, Redis restart drill, or physical printer check. Real MinIO and Redis are required for the complete integration suite; browser suites use isolated MongoDB fixtures and mock direct media transfer. See [test strategy](testing.md) and [invariant matrix](test-matrix.md).

With the complete stack healthy, use an isolated local account and test data to check: public menu at 360/390/430 px; customer signup/login, cart, fake payment success/failure/pending and order access; owner/cashier sign-in and capability differences; category/product/media CRUD; inventory approval; settings save/conflict; order/invoice/print status; bridge disconnect/reconnect; mobile dashboard navigation; keyboard focus and screen-reader labels. Confirm no horizontal overflow or console/hydration errors. Do not use a live payment provider for this local pass. Check `GET /api/health/live` (process only), `GET /api/health/ready` (all dependencies), and realtime `GET /ready` on its configured port. Readiness must be green before accepting operational traffic; a healthy liveness response alone is insufficient.

Inspect browser traces/screenshots in ignored `test-results/` and `playwright-report/`. Do not commit those artifacts. Run `git status --short` and `git ls-files .env.local .env.bridge.local data test-results playwright-report` before handoff; no secret/runtime artifact should be tracked. The operator still must review real owner credentials and printer settings privately.

- Deployment decisions: [deployment checklist](deployment-checklist.md). It is intentionally unsigned until the full stack and real printer have been exercised.

Known limitations: no live Iranian payment gateway adapter has been selected or implemented; the fake provider cannot be used in production. The archived MinIO community image is a local-development choice only, not an approved production storage distribution. The CSP still permits framework-required inline script/style, and the network-wide auth rate bucket needs a trusted ingress design before scaling. The catalog cache is process-local; multi-instance cache coordination is not implemented. The printer bridge can confirm transport/spool acceptance but cannot prove physical paper output without device-specific feedback. The standalone outbox worker has no handlers. The requested QR-table number (`/?table=3` through cart, order and receipt) is not yet implemented and must be included in a later acceptance pass before claiming the final project definition of done. These are release decisions or work items, not reasons to bypass readiness, authorization, or payment verification.
