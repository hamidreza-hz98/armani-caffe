# Mobile storefront shell

Task 27 implements the shared mobile-only frame from `../STITCH_UI_PROMPTS.md` Prompt 01 and `UI-UX/screens/navigation-contact.png`. The design is centered at a maximum width of 480px; it does not add desktop navigation. The RTL header, contact sheet, and footer remain in place across `/`, `/account`, and `/cart`. The menu, account forms, and cart content are separate upcoming storefront tasks; the latter two paths currently show honest, non-transactional placeholders instead of 404 pages.

The route-group layout is a Server Component. It calls the settings and authentication application services directly, never an internal HTTP route. A verified customer cookie yields profile display name and current cart item count; a missing or invalid cookie yields the guest state. A bounded settings/session read gives a degraded-data notice if dependencies are unavailable, and does not turn a database outage into fabricated contact details. The contact bottom sheet is the only interactive Client Component in the shell. The signed-in `/internal/storefront-preview` is a clearly labelled visual fixture, not an authentication bypass or a source of live customer data.

Contact links have a display-boundary allowlist as defense in depth: E.164 `tel:`, `wa.me` for configured Iranian mobiles, exact Instagram/Telegram hosts and path shapes, and a generated Google Maps coordinate URL. Empty or malformed legacy values are never rendered as links. The current contact settings model has one phone field, not distinct fixed/mobile numbers; the sheet shows only configured channels. The required copyright and [developer Instagram profile](https://www.instagram.com/hamidreza_hz98) are fixed footer content.

The header uses 44px controls and a compact visible account label at all three tested widths. The sheet provides a drag-handle visual, close/escape/backdrop behavior via MUI Drawer, keyboard focus management, a bounded scroll region, and safe-area bottom padding. RTL text, LTR contact values, reduced motion, and three viewport sizes are covered by existing foundation rules and focused tests. Offline mode means graceful display of static shell content and a retry instruction; it does not claim transactional cart/account functionality while the backend is unreachable.

Validation: `npm run test:unit`, `npm run test:e2e`, `npm run build`, `npm run lint`, `npm run typecheck`, and `npm run check:architecture`. The E2E suite exercises guest at 360×800, 390×844, 430×932 and the signed-in visual preview at 390×844, including axe checks. Backend authentication and cart integration tests remain the authority for real signed-in behavior.
