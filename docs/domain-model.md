# Domain model and index plan

This is the model contract for Phase 1 before CRUD. Every record has MongoDB `_id`, UTC BSON `createdAt`/`updatedAt`, and `__v`; mutable aggregates use Mongoose optimistic concurrency. Browser-safe, readonly domain DTOs live in each module's `domain/` public export. Mongoose schemas live only in the module's `infrastructure/` and are exported through its server-only boundary; **Mongoose documents are never API contracts**. The `TomanAmount` and `UtcTimestamp` constructors reject fractional/unsafe/negative money and non-canonical UTC input. Jalali is only for UI display and input conversion, never persistence.

Historical snapshots deliberately duplicate catalog names, addition names and integer prices, and carry `snapshotVersion: 1` for future readers. Editing or deleting a product/category/addition cannot change an issued order or invoice. Order and invoice totals are checked against their lines at schema validation, and their snapshot paths are marked immutable. Mutations must still use module application services, conditional writes and transactions; direct MongoDB collection updates can bypass Mongoose hooks/immutability. The eventual CRUD layer must enforce state transitions and ownership on every write, not merely trust these schema defenses.

Secondary state rules: order payment moves unpaid → pending/paid, pending → unpaid/paid, paid → refunded; refunded is terminal. Invoice issued → voided is terminal and requires `voidedAt`. Admin active/disabled and customer active/blocked can be toggled only by authorized application services. Category draft/published can be toggled while not deleted. Product draft ↔ published → archived; archived products require an explicit restoration workflow rather than silent republishing. Inventory active → archived is terminal. A retryable failed print job may return to queued; a delivered or dead outbox event can return to pending only through explicit operator replay with the same idempotency key. State changes must be conditional on the current state and version, preventing stale writers from skipping transitions.

## Index and migration rules

Each owning schema declares named indexes. `src/server/database/business-indexes.ts` gathers definitions through module server boundaries without compiling models or opening a connection. `npm run db:indexes:plan` is read-only; `npm run db:indexes:apply -- --apply` creates missing indexes deliberately and never drops unexpected ones. Unique indexes are the final concurrency guard for identity, slugs, invoice/order codes, and idempotency. Text search indexes are limited to catalog/customer/inventory names and descriptions; phone lookup uses normalized exact matches. Status/date compound indexes support admin lists; queue indexes support claim/retry scans. TTL is limited to ephemeral sessions/carts and delivered outbox events—not orders, payments, invoices, movements, or audits.

Reference integrity is an application/transaction concern because MongoDB ObjectIds are not foreign keys. A category/product/media reference must be checked before write. Stock approval, order placement, payment settlement, invoicing, stock movement and outbox publication will use one transaction where they affect multiple collections. No schema migration or index synchronization occurs during a normal HTTP request.
