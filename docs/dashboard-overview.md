# Dashboard overview (Task 34)

`/dashboard?range=30` is the default; `range=7` changes only the sales cards and daily trend. Unknown values fall back to 30. The date windows are inclusive Tehran calendar days over UTC order timestamps. The 30-day product/customer rankings remain explicitly labelled 30 days. OWNER sees financial metrics and rankings; CASHIER sees only order and stock operations. Every read follows server-side admin session and capability checks. The page calls the analytics reader directly, not its own HTTP endpoint.

The order-attention and low-stock cards stream first; sales metrics, trend, latest orders, stock details, and rankings have independent Suspense fallbacks. Each section catches and logs its own read failure, shows a safe Persian message and a reload link, and does not suppress sibling sections. An empty café displays zero metrics and distinct empty messages. The chart is a viewport-triggered dynamic client island; a server-rendered day-by-day table is available in its disclosure so the values are not encoded only in color or shape. Client charting has no external chart library.

Response budgets: each MongoDB query has a 2.5-second timeout and no disk spill; list responses are capped at ten and the chart at 30 points. Target first dashboard shell response is under 1 second and fully streamed overview under 3 seconds on the local small-business dataset. Target incremental chart JS is under 10 KiB gzip, while total dashboard JS (including MUI shell) is tracked separately. The chart-specific chunk in the Task 34 production build measured 821 bytes gzip. These are performance targets, not guarantees of network or database latency. `npm run test:e2e:dashboard` exercises owner/cashier rendering and narrow layouts against an isolated database; `tests/integration/analytics.test.ts` reconciles overview numbers with the established analytics fixtures. Production timings should be monitored before declaring the latency target met.

If query volume grows, use the versioned Tehran-day rollup plan in [dashboard-analytics.md](dashboard-analytics.md); retain live indexed order and stock attention queries.
