# Dashboard media workflow

`/dashboard/media` is a paginated, server-rendered library. Search, format, visibility, status, and sort are URL filters. Owners may select, edit, replace, and delete assets; cashiers can only view assets allowed by the media service. The product editor shares the same ready/public media picker. The details panel shows usage references and blocks deletion while an asset is in use. Category-image references must be changed through category editing rather than the product replacement operation.

`/dashboard/media/upload` accepts JPEG, PNG, and WebP, from 1 byte through 10 MiB per file. These are the backend policy limits, even if older design mockups depict other types. The browser requests a short-lived presigned POST from `/api/media`, uploads a `FormData` body directly to the returned MinIO URL using `XMLHttpRequest`, then calls `/api/media/:id/complete`. The Next.js process never receives the upload body. At most two transfers are active at once. Each item has its own idempotency key and result, so one failure does not discard successful files. Same-name/size/type/mtime files are de-duplicated within a queue, not globally.

After a successful direct transfer, the pending asset ID is stored in browser session storage until completion. If completion fails or the tab closes, the operator can retry finalization from the recovery panel without re-uploading bytes. A failed transfer instead requests a refreshed presigned ticket with the same idempotency key. Server-side pending-upload cleanup remains available via `npm run media:cleanup`; uploads cancelled before transfer may leave a pending record until that cleanup. Browser session storage contains only pending IDs, not image bytes or credentials.

For local use, start and initialize MinIO as described in [local-infrastructure.md](./local-infrastructure.md). The `MINIO_ENDPOINT` used to sign POST policies must resolve in the operator's browser as well as from the Next.js server. Set `MINIO_CORS_ORIGINS` to the actual dashboard origin and rerun `npm run infra:init:minio` after changing it. In production, use a browser-reachable TLS endpoint suitable for presigned requests; the signature authorizes each upload, while the bucket itself remains private. Proxying upload bodies through Next.js is intentionally unsupported.

Run `npm run test:e2e:media` for browser tests with an isolated Mongo replica set and mocked direct-storage transfer. The media integration suite exercises real MinIO separately when that service is available. The browser tests do not prove live MinIO connectivity; verify it during deployment with a small real upload and a private-object access check.
