# Business and operations settings

Only an authenticated `OWNER` can open `/dashboard/settings/business`, `/contact`, `/seo`, or `/printing` or write their settings. All writes use the existing revision-checked, idempotent settings endpoint and emit an audit event plus a `settings.updated` outbox event. Conflicts require reloading the current server revision; unsaved navigation is confirmed. Cashiers retain only the limited server-side settings reads already allowed by the capability map.

Business identity accepts public, ready Media Library image IDs for the storefront logo and favicon. The settings transaction writes media usage references, so in-use images cannot be deleted. Existing stored business documents without these fields read as `null`; no automatic migration runs in request handling. The storefront layout reads the current settings revision for title, description, robots and favicon metadata on each dynamic request; its header and contact sheet also read the current revision. The default icon remains `/armani-icon.svg`. New invoices read business, contact and print settings transactionally and snapshot them; existing invoices never change.

Contact links are constrained to canonical international telephone, approved HTTPS Instagram/Telegram profile forms, and bounded Google Maps coordinates. The admin map preview opens a generated Google Maps navigation URL; arbitrary iframe HTML is never stored or rendered. SEO preview is indicative, not a promise of search-engine presentation. Dashboard metadata remains static and noindex.

Printing preferences support 58/80 mm, one to three copies, a registered bridge ID, automatic-print toggle, footer, and a write-only encrypted bridge token. The **browser print test** makes a clearly marked diagnostic sheet and an audit event. It does not create an order, invoice, Redis job, or bridge delivery, and is not a hardware-connectivity test. The signed preview URL expires after two minutes and remains owner-authenticated.

Run `npm run test:e2e:business-settings` for the browser journey, or `npm run test:unit` and `npm run test:integration` for contracts and media-reference transactions. The E2E script requires the project's isolated test database and browser setup. On a low-space Windows drive, point `TEMP` and `TMP` to a test-only directory on a drive with at least 500 MB free for the MongoDB replica set.
